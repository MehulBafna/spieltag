Is it any good?

Two questions. Would the method have worked on past seasons, and is it working now? The first answer comes from a walk-forward backtest, where every forecast only used results that were already known. The second comes from forecasts sealed before the match.

How it stays honest

Sealed once
Each forecast is a separate file written with a conditional write. A second write for the same match is refused by the storage service itself, and every file carries a fingerprint that exposes edits.
Only what was known
Models learn from results that were final when the forecast was sealed, and ratings and form are rebuilt as of that moment. A result counts as known three hours after kickoff.
Same code as the backtest
A replay test runs a simulated season hour by hour and checks that the live pipeline's forecasts equal the backtest's, to the last digit.
The live line is separate
While a match is played, a second estimate updates every five minutes from the score and the clock. It is stored apart from the sealed forecast, never replaces it, and is scored on its own at minutes 15, 30, 45, 60 and 75. It knows nothing about cards, substitutions or injuries.
Misses are counted
If a run is missed, the match is reported as missed and an alarm fires. A forecast is never written after kickoff, and never backfilled.
